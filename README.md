# Яндекс Алиса + GPT-6.1 Sol + Serper на Vercel

Вебхук `/api` принимает реплики из Яндекс Диалогов, запускает подготовку ответа в OpenAI Responses API и возвращает короткий ответ для озвучивания Алисой. Если модели нужно больше времени, Алиса сообщает об ожидании; получить результат можно следующей командой «Готово?» или «Дальше». Для вопросов об актуальных событиях и явных просьб найти информацию подключается Serper. По умолчанию используется модель `gpt-6.1-sol`.

Проект работает на Node.js 22 или новее, использует встроенный `fetch` и не требует Redis, отдельной базы данных или дополнительных npm-зависимостей.

## Обновление уже подключенного проекта

1. Сохраните изменения этого репозитория в GitHub. Если он уже связан с Vercel, дождитесь сборки новой версии.
2. В Vercel откройте проект → **Settings → Environment Variables** и проверьте переменные из таблицы ниже. Для рабочего навыка выберите окружение **Production**.
3. После изменения переменных откройте **Deployments**, выполните **Redeploy** последнего Production-развертывания и дождитесь **Ready**. Новые значения применяются при новом развертывании.
4. В настройках навыка Яндекс Диалогов сохраните **Webhook URL**: HTTPS-адрес Production-домена проекта Vercel с путем `/api`.
5. Включите **«Использовать хранилище данных в навыке»**, чтобы Алиса передавала состояние между репликами.
6. Проверьте навык во вкладке **«Тестирование»** по шагам ниже.

Название репозитория может оставаться `alice-gemini-serper-template`: оно не определяет используемую модель. Ключи и настройки Gemini этому коду больше не нужны.

## Переменные окружения

| Переменная | Назначение | Значение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Обязательный ключ OpenAI | Ключ проекта в вашей API-организации OpenAI |
| `SERPER_API_KEY` | Ключ поиска Serper | Ключ из [Serper](https://serper.dev) |
| `OPENAI_MODEL` | Модель для генерации | `gpt-6.1-sol` по умолчанию |
| `OPENAI_REASONING_EFFORT` | Усилие рассуждения | `low` по умолчанию |
| `OPENAI_MAX_OUTPUT_TOKENS` | Предел выходных токенов, включая рассуждение | `1200` по умолчанию |

Если `OPENAI_MODEL` не задана, для совместимости читается прежняя переменная `GPT_MODEL`. Проверьте ее значение: для GPT-6.1 Sol нужен точный идентификатор `gpt-6.1-sol`. Приоритет имеет `OPENAI_MODEL`.

`SERPER_API_KEY` нужен для поиска. Если ключ не задан или поисковый сервис не ответил вовремя, обычные ответы OpenAI продолжают работать. Навык не должен выдавать непроверенные сведения за результат свежего поиска.

Ключ OpenAI должен принадлежать той API-организации, где активированы ваши API-кредиты. Создать ключ можно в [API Platform](https://platform.openai.com/api-keys). Вводите секретные значения в Vercel; не добавляйте их в исходный код или репозиторий. Файл `.env.example` показывает только имена переменных.

## Проверка через Яндекс Диалоги

1. Откройте навык → **«Тестирование»**. Начало разговора должно возвращать приветствие.
2. Отправьте **«Почему небо голубое? Ответь одним предложением»**. Приветствие само по себе не проверяет доступ к OpenAI.
3. Если ответ еще готовится, немного подождите и отправьте **«Готово?»** или **«Дальше»**. Повторяйте команду, пока навык не вернет готовый ответ. Каждый такой запрос проверяет уже запущенную генерацию, а не создает ее заново.
4. После получения ответа спросите **«А почему на закате оно красное?»**, чтобы проверить продолжение разговора. Если потребуется, снова запросите готовый результат.
5. Отправьте **«Найди последние новости космонавтики»**, чтобы проверить путь с поиском Serper.
6. Для проверки отмены задайте новый вопрос и, если навык сообщил об ожидании, отправьте **«Отмена»**. После подтверждения отмены можно задать другой вопрос.
7. В [статистике OpenAI](https://platform.openai.com/usage) проверьте появление запросов в нужной организации. Если поиск включен, проверьте расход запросов и в кабинете Serper.

Для голосовой проверки опубликованного навыка используйте **«Алиса, запусти навык Чипи Чапа»**. На устройстве должен быть аккаунт владельца приватного навыка или аккаунт, которому выдали доступ. Приватный навык не отображается в общем каталоге. Если Алиса не находит его по имени, проверьте аккаунт, распознавание названия и доступные устройства. Это отдельный этап от обработки вопросов вебхуком.

Документация Яндекса: [тестирование навыка](https://yandex.ru/dev/dialogs/alice/doc/ru/test), [доступ к приватному навыку](https://yandex.ru/dev/dialogs/alice/doc/ru/access).

## Как получить ответ, которому нужно больше времени

При новом вопросе сервер создает ответ OpenAI с `background: true` и `store: true`. Модель продолжает работу на стороне OpenAI после того, как вебхук вернул Алисе сообщение об ожидании. Если OpenAI уже успел завершить ответ, навык озвучивает его сразу.

Пока ответ готовится:

- **«Готово?»** или **«Дальше»** — проверить результат существующего запроса. Если он готов, Алиса озвучит его
- **«Отмена»** — отправить отмену текущего запроса в OpenAI
- Новый вопрос — навык предложит сначала получить предыдущий ответ или отменить его; параллельная генерация не запускается

**Алиса не начнет озвучивать готовый ответ сама.** После сообщения об ожидании нужна следующая команда пользователя. Это не непрерывное ожидание на колонке: каждая команда запускает отдельную короткую проверку.

Ожидание привязано к текущей сессии навыка. После выхода из навыка или начала новой сессии незавершенный запрос автоматически не подхватится. Выход из навыка сам по себе не отправляет отмену в OpenAI; чтобы остановить генерацию, перед выходом используйте команду **«Отмена»**.

## Контекст разговора

После готового ответа его идентификатор передается в `session_state`. При следующем вопросе он используется как `previous_response_id`, чтобы OpenAI продолжил разговор. Пока новая генерация не закончена, в состоянии дополнительно хранятся ее идентификатор и укороченный исходный вопрос. Команды «Готово?» и «Дальше» получают этот результат по идентификатору, не повторяя исходный вопрос модели.

Небольшая резервная история также передается в состоянии навыка. Все состояние, включая идентификатор ожидаемого ответа, ограничивается 1 КБ; Redis и отдельная база данных не нужны.

Хранение контекста и фоновая генерация требуют сохраненных ответов OpenAI API. Это не дает навыку доступ к перепискам или памяти аккаунта ChatGPT. Контекст текущего навыка и этого чата независимы.

## Время ответа

Яндекс Диалоги ждут полный ответ от вебхука не более 4,5 секунды, включая сеть. Код ограничивает обработку каждой реплики примерно 4 секундами и оставляет резерв для передачи ответа Алисе. Поиску Serper выделено до 600 мс из этого времени.

Сама генерация GPT-6.1 Sol идет в фоне и может длиться дольше одного обращения Алисы. Создание, проверка готовности и отмена запроса — отдельные короткие HTTP-операции. При ошибке API или нехватке времени на такую операцию сервер возвращает понятное сообщение. Увеличение `maxDuration` Vercel не увеличивает лимит ожидания Яндекс Диалогов.

## Если навык отвечает ошибкой

1. Проверьте `OPENAI_API_KEY`, организацию OpenAI и наличие активных кредитов.
2. Задайте `OPENAI_MODEL=gpt-6.1-sol`. Уберите устаревшее значение `GPT_MODEL`, если оно конфликтует с выбранной моделью.
3. Убедитесь, что переменные доступны в **Production**, и выполните **Redeploy** после их изменения.
4. Проверьте, что Яндекс Диалоги обращаются к Production-домену Vercel с путем `/api`.
5. Проверьте логи последнего развертывания. Ошибки OpenAI и Serper обрабатываются отдельно.

## Новое размещение

В [Vercel](https://vercel.com/dashboard) выберите **Add New → Project**, импортируйте этот репозиторий GitHub и разверните проект. Затем задайте переменные из таблицы, выполните **Redeploy** и сохраните адрес `/api` в Яндекс Диалогах.

Если проект передан ZIP-архивом, распакуйте его и загрузите содержимое в репозиторий GitHub с сохранением папки `api` и файла `api/index.js`. После этого импортируйте репозиторий в Vercel.

## Локальная проверка кода

Установленный Node.js нужен только для разработки и тестов; для настройки готового навыка на Vercel устанавливать его на свой компьютер не требуется.

```bash
npm test
```

Тесты выполняются встроенным модулем Node.js, подменяют внешние API и не расходуют реальные ключи.
